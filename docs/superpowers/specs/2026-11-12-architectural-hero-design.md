# Architectural hero on main

The user approved a wider, tighter hero with a separate architectural 3D object, then explicitly requested review, Copilot conversation resolution and merge into `main`. The original candidate targeted the older `landing` branch. `main` is the canonical static-first site with newer public-truth, onboarding, native download, privacy and support contracts; its content and behavior must be preserved during integration.

The final implementation uses `main`'s ratified headline, maturity-qualified description, active product registry, canonical three-command foundation, shared navigation/theme controls and static proof. A homepage-only layout option widens the shared shell to 1440 px of content and reduces hero vertical padding. Secondary routes retain their existing measure. The flat canonical mark stays in the header and hero eyebrow; the architectural illustration is separate.

The object comprises beveled graphite, violet and ivory frames with local studio lighting. A small lifecycle controller dynamically imports bundled Three.js only for eligible visible desktops. A 21 KiB transparent poster exported from the same scene is present in authored HTML. Mobile, reduced motion, unavailable/lost WebGL and loading failure retain that poster. Pause survives eligibility changes; hidden/offscreen sessions stop rendering. Eligibility and visibility are rechecked after asynchronous loading, before WebGL resources are mounted.

Canonical visual evidence: `OpenCoven/brand` at `798e2f5f2f1a69f5d156ccc0a9aafc4f7da55fc8`, its web profile and usage contract. Main's pinned brand/UI manifests, public positioning and product registry remain authoritative. No claim, privacy policy, analytics mode, authorization, download infrastructure, structured data or deployment configuration is changed.

The old landing-specific board, outcome wrappers and emergency layout CSS are not imported into main. This resolves the obsolete mobile-padding comment by retaining main's deletion of those components. The pending-import visibility comment is fixed directly and covered by a delayed-import/offscreen regression that failed before the fix and passed afterward.

Measured main candidate: 1440 px content at 1920/2560 viewports, next section at y=569 there and y=513 at 1440. At 320, 720, 1440, 1920 and 2560 px, no horizontal overflow was observed. These measurements supersede the earlier landing-only board coordinates. Browser rendering is local Chromium evidence; physical-device and human screen-reader acceptance remain separate.
